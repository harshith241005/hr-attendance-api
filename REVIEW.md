# REVIEW.md

List every defect you found in the starter `app/main.py` (helpers and endpoints). For each one:

| # | Where (function / line) | What is wrong | How you'd notice it (test, input, or symptom) | How you fixed it |
|---|---|---|---|---|
| 1 | `compute_late_minutes` (lines 33–37) | Grace period check `minutes > 10` tests `int((punch_in - start).total_seconds() / 60) > 10`. For 09:40:01 (10m 1s late), integer division yields 10; `10 > 10` evaluates to False, returning 0 instead of 10 (violating R2). | Test punch-in at 09:40:01 for a 09:30 shift returns 0 late minutes instead of 10. | Tested strictly greater than 600 total seconds `(punch_in - start).total_seconds() > 600` and returned floor minutes `int(diff_sec // 60)`. |
| 2 | `compute_late_minutes` (lines 33–37) | Direct datetime replacement `punch_in.replace(hour=h, minute=m, ...)` ignores that shift times are in IST while punch times are UTC / naive datetimes, causing a 5.5h offset. Also fails overnight morning punch-ins. | Punch-in at 09:35 IST (04:05 UTC) calculates late minutes against 09:30 UTC instead of 09:30 IST. | Converted `punch_in` to IST timezone, constructed shift start on the attendance date in IST, and properly handled overnight shift day boundaries. |
| 3 | `compute_work_hours` (lines 40–41) | Uses Python built-in `round(..., 2)` which performs round-half-to-even (banker's rounding) instead of round-half-up (R4, R8). | Total duration 8.425 hours rounds down to 8.42 instead of rounding up to 8.43. | Implemented half-up rounding using `decimal.Decimal` with `ROUND_HALF_UP` quantized to 2 decimal places. |
| 4 | `compute_overtime` (lines 44–47) | Computes `max(0, minutes)` without applying the 30-minute minimum threshold (R3). | Punch-out 15 minutes after shift end returns 15 overtime minutes instead of 0. | Added threshold check: returns calculated floor minutes only if >= 30, otherwise returns 0. |
| 5 | `compute_overtime` (lines 44–47) | Anchors `shift_end` to `date_str` even for overnight shifts (`shift_end <= shift_start`), where shift end falls on `date_str + 1 day`. | Overnight shift (22:00 - 06:00) punching out at 06:40 computes negative or erroneous overtime. | Added logic adding +1 day to shift end date when `shift_end <= shift_start`. |
| 6 | `GET /health` (lines 72–74) | Returns static `{"status": "ok"}` without querying the database, violating contract requirement to return 200 only when MongoDB answers a ping, else 503. | Stopping MongoDB still returns 200 OK from `/health`. | Pings MongoDB via `client.admin.command('ping')` in a try/except block, raising HTTP 503 on failure. |
| 7 | `POST /employees` (lines 77–85) | Concurrency race condition: Uses check-then-insert (`find_one` then `insert_one`), permitting duplicate employee creation under parallel identical requests. | Concurrent POST requests with identical `emp_code` result in duplicates or unhandled 500 errors. | Created a unique index on `emp_code` at startup and caught PyMongo `DuplicateKeyError` to return HTTP 409. |
| 8 | `POST /employees` (lines 53–61, 77–85) | Missing Pydantic schema validation: Does not validate `emp_code` regex (`^EMP\d{4,6}$`), email regex, or the rule that `shift_start != shift_end`. Also stores `created_at` as local naive datetime. | Submitting `shift_start == shift_end` or invalid email yields 201 instead of 422. | Added field regexes and validators to `EmployeeCreate`, ensured UTC datetime truncated to seconds, and serialized `created_at` to epoch milliseconds. |
| 9 | `GET /employees` (lines 88–96) | Broken pagination offset: `skip = page * page_size`. For page 1, `skip = 20`, completely skipping the first 20 records. | Calling `GET /employees?page=1` skips the first page of results. | Corrected pagination formula to `skip = (page - 1) * page_size`. |
| 10 | `GET /employees` (lines 88–96) | Total count ignores filters and results are unsorted: `count_documents({})` counts entire collection, and query lacks `.sort("emp_code", 1)`. | Requesting employees with `department=Engineering` reports the total of all departments. | Used `count_documents(q)` and added `.sort("emp_code", 1)` with parameter bounds validation (`page >= 1`, `1 <= page_size <= 100`). |
| 11 | `POST /attendance/punch-in` (lines 99–122) | Concurrency race condition: Relies on `find_one` check-then-insert instead of database unique constraint. | Two parallel punch-ins for the same employee and date both insert documents. | Created unique compound index on `(emp_code, date)` and caught `DuplicateKeyError` to return HTTP 409. |
| 12 | `POST /attendance/punch-in` (lines 99–122) | Unhandled non-existent employee: When `emp_code` is unknown, `emp` is None, crashing on line 113 with `TypeError` (HTTP 500) instead of HTTP 404. | Punch-in request for unknown employee returns HTTP 500. | Added explicit check `if not emp: raise HTTPException(404, "Employee not found")`. |
| 13 | `POST /attendance/punch-in` (lines 99–122) | Local timezone and un-truncated instants: `fromtimestamp` uses host machine timezone, and does not truncate instants to whole seconds (R1). | Host timezone offsets shift date, and sub-second millisecond residuals persist. | Converted timestamps using UTC timezone, truncated milliseconds with `(ts // 1000) * 1000`, and evaluated IST attendance date including overnight shifts. |
| 14 | `POST /attendance/punch-in` (lines 99–122) | Contract violation: Injects `id = str(res.inserted_id)` into response and returns raw datetimes instead of epoch milliseconds. | Response JSON contains unexpected `id` key, violating the OpenAPI schema. | Removed `id` field from response and formatted all instants to epoch milliseconds. |
| 15 | `GET /attendance` (lines 124–150) | Scalability / memory failure: Loads entire collection into Python memory with `list(db.attendance_logs.find(q))` and sorts in Python. | At 100k documents, memory usage spikes and response times degrade significantly. | Shifted filtering, sorting, and pagination into MongoDB query operations backed by compound indexes. |
| 16 | `GET /attendance` (lines 124–150) | Incomplete sorting and unvalidated dates: Sorts only by `date` desc (missing secondary sort `emp_code` asc), and does not reject `date_from > date_to`. | Query with `date_from > date_to` succeeds with empty list instead of 422; tied dates have non-deterministic order. | Added secondary sort `.sort([("date", -1), ("emp_code", 1)])` and raised 422 if `date_from > date_to`. |
| 17 | Configuration (lines 20–24) | `MongoClient` initialized without `tz_aware=True`, producing naive datetimes that lead to timezone ambiguity. Also lacks startup index creation. | Query planner falls back to collection scans (`COLLSCAN`), and datetime conversions lose UTC context. | Added `tz_aware=True` to `MongoClient` and implemented idempotent index creation in FastAPI `lifespan`. |

### Also note anything you looked at and decided was not a defect, and why:

1. **FastAPI Application Metadata:** `app = FastAPI(title="Employee Attendance & Analytics API", version="2.0.0")` matches the exact title and version specified in `openapi.yaml`.
